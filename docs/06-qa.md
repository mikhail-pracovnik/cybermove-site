# 06 — QA loop & Definition of Done

## Verification loop (run at the end, repeat until everything passes)

1. `npm run build` — zero errors, zero warnings you introduced.
2. `npm run preview` in the background (port 4321).
3. Install Playwright once: `npm i -D @playwright/test` then `npx playwright install chromium`.
4. `tests/qa.spec.ts` must, for **every page × both languages × two viewports** (iPhone 13: 390×844, Desktop: 1440×900):
   - load the page, wait for `document.fonts.ready`;
   - assert no console errors and no failed requests (4xx/5xx);
   - assert `document.documentElement.scrollWidth <= window.innerWidth` (no horizontal scroll) — also at 320 px width;
   - assert exactly one `h1`, `html[lang]` correct, `link[hreflang]` ×3 present, canonical present;
   - assert no visible text matches `/lorem|todo|undefined|null|example\.com|\{\{|\}\}/i`;
   - scroll to the bottom in steps (to trigger reveals), then take a **full-page screenshot** to `qa/screens/<lang>-<page>-<viewport>.png`;
   - with `reducedMotion: 'reduce'` context: every `.reveal` element is visible after load.
5. Interaction checks (desktop Chromium):
   - nav capsule: after scrolling 600 px the header has the capsule state; menu button opens the panel; Esc closes it; focus returns.
   - home window click → URL changes to the target page.
   - projects: clicking a sector chip reduces the number of visible cards to the sector count; clicking a card opens a dialog; Esc closes it; `?p=<id>` opens it directly.
   - estimator: moving a slider changes the result text.
   - contact: `?need=ai` preselects the AI chip; submitting an empty form shows validation errors; a valid form calls `window.open` with a `wa.me` URL (stub `window.open`).
   - language switch on each page leads to the correct alternate URL (HTTP 200).
6. Link check: crawl all internal `<a href>` from the built `dist/` and assert each resolves to an existing file.
7. **Look at every screenshot yourself.** Check: alignment to the grid, heading wrapping in RU at 390 px (no ugly one-word lines, no overflow), consistent portrait treatment, alternating themes, nothing overlapping the capsule nav, footer bending text fully visible. Fix and re-run.
8. Performance: run Lighthouse if available (`npx lighthouse http://localhost:4321/ --preset=perf --form-factor=mobile --quiet --chrome-flags="--headless"`); otherwise use Playwright + CDP to throttle CPU 4× and record a trace while scrolling the home page — no long tasks > 50 ms during scroll, and report bundle sizes from `dist/` (gzip sizes via a small Node script).

## Definition of Done

- [ ] All 8 pages exist in RU and EN, built to `dist/`, open without errors.
- [ ] All copy comes from `content/`; no invented text, numbers, emails, or links.
- [ ] Six signature interactions work on desktop Chrome; degrade gracefully (no errors) in a browser without View Transitions; all have reduced-motion variants.
- [ ] Native cursor always visible; no lagging follower.
- [ ] Mobile (390 px) is designed, not squeezed: nav capsule + bottom sheet menu, stacked windows, readable headings, ≥ 44 px tap targets, no horizontal scroll at 320 px.
- [ ] Contact form validates and opens WhatsApp with a formatted message; works without JS (link fallback).
- [ ] hreflang, canonical, sitemap, robots, OG image, favicon, JSON-LD in place.
- [ ] Budgets from `05-tech.md` met or the gap reported honestly with numbers.
- [ ] `public/.htaccess` with redirects, caching, 404, HTTPS.
- [ ] `REPORT.md` written in Russian (see CLAUDE.md phase 9) with open questions from `08-open-questions.md` that remain unresolved.
- [ ] `qa/screens/` contains the final screenshots.
